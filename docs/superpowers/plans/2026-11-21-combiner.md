# The Combiner Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `/combiner` page where a visitor pools 2+ taxing districts' ADM and spending and sees each member town's homestead education tax rate today vs pooled.

**Architecture:** A new pure module `model/src/combine.ts` builds a pooled membership with the existing `combineMembership`, runs `perPupilEducationSpending` → `townRate` once per member town for both "today" (each district alone) and "pooled". A new per-town CLA importer plus a build step produce `combiner.json` for the site; an Astro page and TS island (mirroring `/model`) are a thin front end with calculation walkthroughs.

**Tech Stack:** TypeScript, Vitest, Astro, npm workspaces (`model`, `tools`, `site`), YAML warehouse files.

**Spec:** `docs/superpowers/specs/2026-11-21-combiner-design.md`

## Global Constraints

- Engine never returns a number it cannot justify; null propagates, with the reason named (which member, which field). Withheld band ranges are never used as values.
- No "savings" field, ranking, scoring or recommendation anywhere. Deltas are signed, both directions equal weight.
- "Today" and "pooled" both come from the engine chain (`tax.ts`); the published rate is a reference column only.
- Pooled spending = sum of members' AOE EdSpend education spending × `consolidation_factor` (default 1.0).
- Pooled Act 84 transition decrease defaults to 0, shown as a labelled assumption with rationale; "today" uses each member's own published decrease.
- A town served by more than one district is "not computable yet: rate blends more than one district".
- FY2026 only initially (only year with CLA data). Parameters are 23/23 verified, not countersigned; the page says so as `/model` does.
- `model/` is pure and dependency-light; `.ts` import specifiers; `npm run typecheck` and `npm test` stay green; `npm run build` succeeds.
- Generated JSON is imported only from `.astro` frontmatter and passed to the island.
- Public text at ~5th-grade reading level (AGENT.md); keep *supervisory union*, *average daily membership*, *common level of appraisal* with a plain gloss on first use.
- Commits end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

- A selected district with no spending or no ADM published → listed in picker as "can't be combined yet: <reason>" and cannot be added; a hand-edited share link naming one yields a named blocker, not a crash.
- Share link naming an unknown district slug or an unsupported year → ignored/flagged on the page, never a blank or thrown error.
- Fewer than 2 districts selected → a plain "pick at least two" message, no table.
- Two districts whose pooled spending-per-pupil is below the excess threshold, so the floor of 1.0 applies → delta shown as zero, not as a savings.
- Blank sparsity/small-school inputs → result names the blank that blocks it (matching how `/model` treats blank), not a silent zero.

### Task 3: The pooling engine — `model/src/combine.ts`

**Files:**
- Create: `model/src/combine.ts`, `model/src/combine.test.ts`
- Modify: `model/src/index.ts` (add `export * from './combine.ts';`)

**Interfaces:**
- Consumes: `createContext`, `input`, `sum`, `product`, `difference`, `notComputable`, `collectBlockers` (`node.ts`); `computeWeightedMembership`, `combineMembership`, `perPupilEducationSpending`, `MembershipInput` (`membership.ts`); `townRate`, `TownTaxInput`, `TransitionInput`, `ExcessSpendingAdjustments`, `TownRateResult` (`tax.ts`).
- Produces:
  ```ts
  export interface CombinerMember {
    entity: string;
    membership: MembershipInput;      // sparsity/small_schools as supplied by the page
    education_spending: number | null;
    act84_decrease: number | null;    // member's own published FY2025 decrease
    towns: readonly TownTaxInput[];   // member's towns with CLA
  }
  export interface CombinerOptions {
    consolidation_factor: number;                 // default 1.0
    pooled_act84_decrease: number;                // default 0
    pooled_persons_per_square_mile: number | null;
    statewide_average_per_pupil: number | null;
    adjustments?: ExcessSpendingAdjustments;
    town_districts: Readonly<Record<string, readonly string[]>>; // town -> every district serving it
  }
  export interface CombinerTownRow {
    town: string; district: string;
    today: TownRateResult | null; pooled: TownRateResult | null;
    delta: number | null;              // pooled.billedRate - today.billedRate, signed
    direction: 'up' | 'down' | 'none' | null;
    notComputable: string | null;      // plain reason
  }
  export interface CombinerResult {
    pooled: { membership: MembershipResult; spending: CalcNode; perPupil: CalcNode };
    members: { entity: string; perPupil: CalcNode }[];
    towns: CombinerTownRow[];
    assumptions: Assumption[];         // consolidation_factor, pooled_act84_decrease, each with rationale
    caveats: string[];
  }
  export function runCombiner(params: ParameterSet, members: readonly CombinerMember[], opts: CombinerOptions): CombinerResult;
  ```
  Page code in Task 4 relies on these names.

- [ ] **Step 1: Write failing tests** in `combine.test.ts` using the synthetic example parameters already used in `engine.test.ts` (copy its fixture setup):
  - `identity`: pooling one member (and `consolidation_factor` 1, pooled decrease equal to that member's) gives `pooled` billedRate equal to `today` for each of its towns.
  - `hand-checkable`: two members with round ADM (e.g. 100 and 200 K–5 pupils, one year, zero poverty/EL/placed) and spending $1,000,000 and $2,400,000; assert pooled weighted ADM and per-pupil equal your hand-computed values (write the arithmetic in a comment).
  - `equal districts`: two identical members → pooled per-pupil equals each member's; every `delta` is 0 and `direction` is `'none'`.
  - `floor`: members whose per-pupil spending is below the excess threshold → delta 0, never negative from the floor.
  - `null propagation`: a withheld band (null), a null spending, and a null poverty count in one member each yield `pooled: null` and a `notComputable` reason that names that member's entity.
  - `multi-district town`: a town listed under two districts in `town_districts` → row `notComputable` contains "blends more than one district".
  - `blank sparsity`: `pooled_persons_per_square_mile: null` → blockers name the blank sparsity density; no number returned.
  - `no savings`: result JSON contains no key matching /saving/i.
  - `golden`: Slate Valley members from `model/` golden fixtures where inputs overlap: pooled per-pupil matches the fixture within rounding stated in that fixture's tolerance.
- [ ] **Step 2:** Run `npx vitest run model/src/combine.test.ts`; expect FAIL.
- [ ] **Step 3:** Implement `runCombiner`: (a) membership for the pool via `combineMembership(ctx, members.map(m=>m.membership), {entity:'pool', persons_per_square_mile: opts.pooled_persons_per_square_mile, small_schools: all members' schools}))`; (b) pooled spending = `product(sum(member spendings), consolidation_factor)`, null if any member null (reason names the member); (c) per member "today" via `computeWeightedMembership` → `perPupilEducationSpending` → `townRate(..., {fy2025RateDecrease: member.act84_decrease})` per own town; (d) pooled via `townRate(..., {fy2025RateDecrease: opts.pooled_act84_decrease})` per town with its own CLA; (e) towns in `town_districts` with >1 district → `notComputable`; (f) `delta`/`direction` from billedRate difference; (g) assumptions as labelled objects with rationale (copy shape from `scenario.ts` `Assumption`); caveats include that the engine can differ from published rates.
- [ ] **Step 4:** Run `npx vitest run model/src/combine.test.ts`; expect PASS. Then `npm run typecheck && npm test`; expect all green.
- [ ] **Step 5: Commit** `git add model/src && git commit -m "feat: combiner engine pools districts and compares town rates"`
